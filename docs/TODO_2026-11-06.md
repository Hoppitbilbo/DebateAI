## 4. Suspicious bugs and risks

1. **Login limit counts the whole class (production).** `server/internal/httpapi/auth.go:99` allows 20 logins per IP every 15 minutes and counts successful logins too, before checking the password. A class of 25 behind one school address: the 21st student is refused for up to 15 minutes. Fixed on p6 (`AuthLimits.Login(ip, identifier)`), not in production.
2. **Wikimedia limits from a school IP.** Wikipedia (bios, search, portraits) and Wiktionary (dictionary) are called straight from each browser. A whole class behind one IP can get HTTP 429 (seen while testing from one machine). Bios fall back to the search snippet and the dictionary says "non risponde", but the content gets poorer. If it shows up in class: cache on the server or proxy with a User-Agent.
3. **The activity can end with the goal reached while the character never answered.** In a test with `autoEnd` on, two student messages ended the activity even though both character replies had failed (Gemini 503): the judge seems to judge on the student's turns alone. To verify in `server/internal/app/judge.go`.
4. **Free-tier Gemini is unreliable.** `gemini-3.8-flash` (the default chat and evaluation model when Gemini is configured from the environment) kept answering 503 "high demand" or timing out after 25 s; `gemini-2.5-flash` answered at once. Check that production routing has a working fallback for chat and evaluation (Admin → AI), and the budget.
5. **"Retry" after the end of an activity** shows "Questa attività è terminata" as a chat error: correct, but it reads like a failure. Small UX fix.
6. **Voice:** "thinking" lasts only a fraction of a second, because Gemini sends the student's transcription together with the first audio; the second of silence before it still reads "listening". The microphone uses `ScriptProcessorNode`, which browsers deprecate (see §5).
7. **Characters chosen before P1** have no `lang` and are read as if picked on the interface's Wikipedia (as before P1). The portrait (`wikiImage.ts`) still follows the interface language.
8. **Approximate word matching (P2):** a word of 5 letters or more counts by its stem ("feconda" for "fecondo"), but no conjugation ("penso" does not count for "pensare"); a short stem can match an unrelated word.
9. **sentry will conflict with `master`** (p6: ✅ rebased on 6/11; conflicts were only `REFACTORING.md`, `check-i18n.mjs` and the five `platform.json`, `api.ts` merged by itself): it starts from `e78f9b4`, and P0–P2 changed `src/lib/api.ts`, the five `platform.json` files and `docs/REFACTORING.md`.

## 5. Refactoring still missing

The phases of `docs/REFACTORING.md` are all ticked (61 tasks). What is left is smaller and comes from the notes and from this week:

- **`scripts/check-i18n.mjs`** checks dynamic keys only from a hand-written list (P1's `live.state.thinking` was missing until P2). Derive the list from the code or test it, so that a new state or error code cannot go untranslated unseen.
- **Microphone capture:** move `liveConversationService.ts` from `ScriptProcessorNode` to an `AudioWorklet`.
- **Wikimedia calls:** `wiki.ts`, `wikiImage.ts`, `WikiSearchSelect.tsx` and `wiktionary.ts` each build their own `fetch` and cache; one small client (cache, error handling, one place to add a server proxy for §4.2) would remove the duplication.
- **Audit leftovers, as written in `REFACTORING.md` › Stato attuale:** resuming an attempt after a reload; the characters' prompt recipe is still built by the browser and the saved `context` is not checked against the assignment; per-app guide lines (skills, length, voices) missing in five languages.

- **The OpenAI-compatible adapter** still sends its own `(start)` user message, now covered by `userFirst` in the gateway (kept on purpose; remove when the adapter is no longer used alone).
